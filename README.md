# نظام مراقبة السائق (DMS)

مشروع **Driver Monitoring System** يهدف إلى استخراج إشارات قابلة للتفسير من وجه السائق لدراسة حالات الانتباه والنعاس باستخدام الرؤية الحاسوبية و**MediaPipe Face Mesh**.

المشروع لا يعتمد في مرحلته الأولى على نموذج تعلم عميق مدرّب للتصنيف، بل يستخدم ميزات هندسية وفيزيولوجية واضحة وقابلة للتفسير، ثم يطبّق قواعد بسيطة على هذه الميزات لتحديد الحالة المتوقعة ومقارنتها بالوسوم الحقيقية. كما يدعم المشروع مسارًا ثانويًا للفيديو يقوم بتحويل كل فيديو إلى سلسلة زمنية من الميزات تمهيدًا لاستخدامها في نماذج زمنية لاحقًا.

> هذا مشروع بحثي/تعليمي، وليس بديلاً عن نظام سلامة معتمد للاستخدام داخل المركبات.

---

## الفكرة العامة

يعتمد النظام على خط معالجة موحّد يبدأ من صورة أو فيديو، ثم يمر بالمراحل التالية:

1. **كشف الوجه** باستخدام MediaPipe.
2. **استخراج معالم الوجه** عبر Face Mesh.
3. **تطبيع المعالم** ثم حساب ميزات هندسية وفيزيولوجية.
4. **تفسير الحالة** في مسار الصور باستخدام قواعد واضحة.
5. **تصدير النتائج** على شكل تقارير أو جداول ميزات أو سلاسل زمنية.

```text
صورة أو فيديو
│
├── كشف الوجه (MediaPipe)
├── MediaPipe Face Mesh واستخراج معالم الوجه
├── تطبيع المعالم وحساب الميزات
│   ├── العين: EAR، انغلاق العين، مؤشر الرمش
│   ├── الفم: MAR، الانفتاح، مؤشر التثاؤب
│   ├── الرأس: Pitch / Yaw / Roll
│   ├── النظرة: الاتجاه الأفقي والرأسي
│   ├── الجودة: الضبابية والإضاءة
│   └── هندسة الوجه والتناظر
├── [الصور فقط] محرّك قواعد: alert / yawning / microsleep
└── تصدير البيانات والتقارير أو السلاسل الزمنية
```

---

## حالات السائق المدعومة

في مسار الصور، يدعم النظام ثلاث حالات رئيسية:

| الحالة | المعنى | منطق التصنيف الافتراضي |
|---|---|---|
| `alert` | السائق منتبه | الحالة الافتراضية عندما لا تتحقق قواعد النعاس أو التثاؤب |
| `yawning` | تثاؤب | عندما تتجاوز قيمة `mar` عتبة التثاؤب |
| `microsleep` | نعاس/إغماض قصير للعين | عندما ينخفض `ear_avg` بشكل ملحوظ أو تُغلق العينان |

العتبات ليست ثابتة علميًا لكل بيئة، ويمكن تعديلها من ملف الإعدادات `configs/default.yaml` ويفضّل معايرتها على بياناتك الخاصة.

- Python 3.10 أو أحدث
- Windows أو Linux أو macOS
- لا حاجة لكاميرا، لأن المشروع يعالج ملفات صور وفيديو موجودة مسبقًا
- يوصى ببطاقة NVIDIA/CUDA لمسار الفيديو الطويل، لكن التنفيذ على CPU مدعوم أيضًا

أهم المكتبات المستخدمة:

- OpenCV
- MediaPipe
- NumPy
- Pandas
- Scikit-learn
- PyArrow
- Matplotlib

# مسار الصور: FL3D والتصنيف بالقواعد

في المرحلة الأولى يعالج النظام صور FL3D، ويستخرج منها الميزات، ثم يطبّق قواعد تصنيف بسيطة، وبعدها يقارن النتيجة بالوسوم الحقيقية ويولّد تقارير التقييم. ويعتمد هذا المسار على **الوسوم الحقيقية للتقييم فقط**، بينما يتم استخراج المعالم داخليًا من MediaPipe بدلًا من الاعتماد على معالم FL3D الجاهزة.

## البيانات المتوقعة

المسار الافتراضي يشير إلى مجلد `classification_frames/`، وتكون ملفات التعليقات وفق أحد الأنماط المحددة في الإعدادات مثل:

```text
annotations_train.json
annotations_val.json
annotations_test.json
```

## التشغيل الكامل

```powershell
py -m dms.pipeline --config configs/default.yaml
```

أو بعد التثبيت:

```powershell
dms --config configs/default.yaml
```

## تشغيل سريع للتجربة

```powershell
# عشر صور من مجموعة التدريب فقط
py -m dms.pipeline --config configs/default.yaml --splits train --max-samples 10
```

## خيارات سطر الأوامر

| الخيار | الوصف |
|---|---|
| `--config` | مسار ملف الإعداد، والافتراضي `configs/default.yaml` |
| `--splits train val test` | التقسيمات المطلوب تشغيلها |
| `--max-samples N` | حد أقصى للعينات في كل تقسيم |
| `--log-level DEBUG` | مستوى السجل |

## مخرجات مسار الصور

يُنشئ كل تشغيل مجلدًا فريدًا داخل `outputs/runs/<timestamp>/`:

| الملف أو المجلد | المحتوى |
|---|---|
| `config_snapshot.json` | نسخة الإعداد المستخدمة |
| `validation_report.json` | فحص سلامة بيانات الإدخال |
| `metrics/evaluation.json` | الدقة وF1 ومصفوفة الالتباس |
| `reports/failure_analysis.json` | تحليل حالات الإخفاق |
| `reports/misclassified.csv` | العينات المصنفة بصورة خاطئة |
| `reports/eda_summary.json` | ملخص إحصائي للميزات |
| `figures/` | رسوم توزيعات وارتباطات ومقارنات |

كما تُحفظ جداول الميزات الموحّدة أيضًا في:

```text
data/features/features_<timestamp>.csv
data/features/features_<timestamp>.parquet
```

# مسار الفيديو: استخراج الميزات الزمنية

المرحلة 1.5 مخصصة لمعالجة الفيديوهات وتحويل كل فيديو إلى **سلسلة زمنية من الميزات**، بحيث يصبح الملف الناتج جاهزًا لاستخدامه لاحقًا في نماذج تسلسلية مثل LSTM أو GRU أو Transformer. المسار لا يطبّق تصنيفًا نهائيًا بالفيديو داخل هذا الجزء، بل يركز على التصدير المنظّم للميزات لكل إطار.

## شكل مجلدات الفيديو

يكتشف المحمّل الفيديوهات داخل الجذور المحددة في `paths.video_data_roots`. الشكل الشائع هو:

```text
Fold5_part2/
├── 55/
│   ├── 0.mp4
│   ├── 5.mp4
│   └── 10.mp4
└── 56/
    └── ...
```

أسماء مجلدات المشاركين يجب أن تطابق التعبير `^\d+$` افتراضيًا. الامتدادات المدعومة حاليًا هي:

- `.mov`
- `.mp4`
- `.avi`
- `.mkv`

ويمكن وضع `labels.csv` اختياريًا في جذر البيانات لربط الفيديوهات بوسومها.

## التشغيل

```powershell
py -m dms.pipeline.video_main --config configs/video_default.yaml
```

أو:

```powershell
dms-video --config configs/video_default.yaml
```

## تشغيل محدود للتحقق

```powershell
py -m dms.pipeline.video_main --config configs/video_default.yaml --max-videos 3
```

## كيف يعمل المسار

- يكتشف الفيديوهات ويرتبها حسب مجلد البيانات والمشارك.
- يقرأ الإطارات تدريجيًا، لذلك لا يحمّل الفيديو كاملًا إلى الذاكرة.
- ينشئ كل عامل (worker) كواشفه وكائنات MediaPipe الخاصة به، ولا تُشارك هذه الكائنات بين العمليات.
- يعالج كل إطار: كشف وجه → معالم → ميزات.
- يسجّل الإطارات الفاشلة داخل الجدول نفسه مع `processing_success=false` وقيم ميزات فارغة (`NaN`) بدلًا من إيقاف الفيديو كله.
- يصدر ملف فشل باسم `<video>_FAILED.json` إذا فشلت معالجة فيديو بالكامل، ثم يكمل بقية الفيديوهات.
- عند تفعيل `skip_existing`، يتجاوز الفيديو الذي يملك ملف Parquet وملف metadata مكتملين.

## المخرجات

لكل فيديو، تُكتب الملفات داخل المسار التالي:

```text
outputs/temporal_features/<fold>/Subject_<id>/<اسم_الفيديو>.parquet
outputs/temporal_features/<fold>/Subject_<id>/<اسم_الفيديو>.csv
outputs/temporal_features/<fold>/Subject_<id>/<اسم_الفيديو>.meta.json
outputs/temporal_features/<fold>/Subject_<id>/feature_schema.json
```

ويحتوي `meta.json` على عدد الإطارات الكلي والمعالج والناجح والفاشل، FPS، الجهاز المستخدم، وحالة الانقطاع. أما `feature_schema.json` فيحفظ ترتيب الأعمدة وإصدار المخطط.

كما يُنشأ ملخص تشغيل عام في:

```text
outputs/video_runs/<timestamp>/config_snapshot.json
outputs/video_runs/<timestamp>/run_summary.json
```

# أعمدة الميزات الزمنية

كل صف يمثل إطار فيديو واحدًا. وتشمل الأعمدة التعريفية:

- `video_id`
- `subject_id`
- `fold_name`
- `frame_index`
- `timestamp_sec`
- `fps`
- `processing_success`

وتشمل الميزات:

| المجموعة | أبرز الميزات |
|---|---|
| العين | `ear_left`, `ear_right`, `ear_avg`, `eye_opening`, `eyes_closed`, `blink_proxy` |
| الفم | `mar`, `mouth_opening`, `mouth_width_norm`, `nose_to_mouth_ratio`, `yawning_indicator` |
| وضعية الرأس | `pitch`, `yaw`, `roll`, `head_pose_valid` |
| اتجاه النظر | `gaze_horizontal`, `gaze_vertical`, `gaze_magnitude`, `gaze_valid` |
| جودة الصورة | `blur`, `brightness`, `detection_confidence`, `face_bbox_area_ratio` |
| هندسة الوجه | `eye_distance`, `eye_distance_norm`, `face_height_ratio`, `face_width_ratio`, `symmetry_score`, `nose_angle`, `vertical_alignment`, `mouth_nose_offset` |

# منطق الحساب

- **EAR**: يحسب كنسبة المسافات العمودية للعين إلى المسافة الأفقية، ثم تُحسب قيمة لكل عين مع متوسط نهائي `ear_avg`.
- **انغلاق العين / الرمش**: `eyes_closed = 1` عندما تكون `ear_avg` أقل من العتبة المحددة، و`blink_proxy` يتبع نفس المنطق في الإطار نفسه.
- **MAR / التثاؤب**: `mar` هو المسافة بين الشفتين مقسومة على عرض الفم، و`yawning_indicator` يساوي 1 عند تجاوز العتبة.
- **وضعية الرأس**: تُقدّر زوايا `pitch` و`yaw` و`roll` باستخدام مطابقة نقاط الوجه مع نموذج ثلاثي الأبعاد مبسط.
- **اتجاه النظر**: يقدّر بطريقة تقريبية بحسب مواضع القزحية أو النمط الهندسي للأنف والعينين.
- **الجودة**: `blur` هو تباين Laplacian، و`brightness` هو متوسط الشدة الضوئية.
- **الهندسة والتناظر**: تُطبّع بعض القياسات بمسافة العينين لتقليل أثر الحجم، وتُحسب درجة التناظر من أزواج معالم محددة.

# إعدادات المشروع

## `configs/default.yaml` — مسار الصور

- `paths.data_root`: موقع صور FL3D وملفات التعليقات.
- `dataset.splits`: التقسيمات المطلوب تشغيلها.
- `detector.provider`: `mediapipe` هو المزود الجاهز.
- `features.enabled_groups`: مجموعات الميزات المراد حسابها.
- `rules.thresholds`: عتبات `MAR` و`EAR` للتصنيف بالقواعد.
- `evaluation.primary_split`: التقسيم الذي تُحسب عليه المقاييس الأساسية.
- `analysis.generate_plots`: تفعيل أو تعطيل الرسوم.

## `configs/video_default.yaml` — مسار الفيديو

- `paths.video_data_roots`: مجلدات الفيديو، مثل `Fold5_part2`.
- `paths.temporal_features_dir`: مكان حفظ السلاسل الزمنية.
- `video.export_formats`: صيغ التصدير (`parquet` و`csv`).
- `video.skip_existing`: يمنع إعادة معالجة فيديو مكتمل.
- `video.max_videos`: حد اختياري لعدد الفيديوهات.
- `video.use_video_landmark_tracking`: تفعيل وضع التتبع الزمني للمعالم.
- `compute.device`: `auto` أو `cpu` أو `cuda`.
- `compute.mediapipe_delegate`: `auto` أو `cpu` أو `gpu`.
- `compute.num_workers`: عدد عمليات معالجة الفيديو المتوازية.
- `compute.frame_buffer_size`: حجم مخزن قراءة الإطارات.

## مخطط المعالم

ملف `configs/landmarks_mediapipe.yaml` يعرّف فهارس MediaPipe المستخدمة لحساب EAR وMAR ووضعية الرأس واتجاه النظر والتناظر. عند تعديله، يجب الحفاظ على توافقه مع إصدار MediaPipe Face Mesh ومع تفعيل `refine_landmarks` عند استخدام فهارس القزحية.

# ملاحظات على الأداء والتشغيل

- جرّب فيديو واحدًا أولًا باستخدام `--max-videos 1`.
- إذا ظهرت مشاكل ذاكرة أو أخطاء مرتبطة بـMediaPipe، اجعل `compute.num_workers: 1`.
- إذا لم يُكتشف أي فيديو، راجع `paths.video_data_roots` والامتدادات ونمط مجلدات المشاركين.
- إذا كانت نتائج `EAR` أو `MAR` غير مناسبة لبياناتك، عاير العتبات على عينة موسومة.
- قد تختلف سرعة التنفيذ بشدة حسب دقة الفيديو وطوله والجهاز وعدد العمال.
- ملفات الفيديو والمخرجات الكبيرة غير مناسبة غالبًا للرفع إلى GitHub؛ احتفظ بالكود والإعدادات فقط، واستخدم تخزينًا خارجيًا للبيانات الكبيرة.
